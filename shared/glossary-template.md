# Glossary template

## Purpose
Provide clear, consistent definitions for technical terms used throughout BSV blockchain workshop materials.

## General blockchain terms
**Address**: A public identifier derived from a public key, used to receive payments.

**Block**: A collection of transactions grouped together and validated by miners.

**Blockchain**: A distributed ledger maintained by a network of nodes using cryptographic proof.

**Confirmation**: The process of including a transaction in a block and subsequent blocks.

**Fee**: Payment to miners for including transactions in blocks.

**Hash**: A fixed-length string produced by a cryptographic hash function.

**Private key**: A secret number used to sign transactions and prove ownership of funds.

**Public key**: A cryptographic key that can be shared publicly for verification purposes.

**Transaction**: A data structure that transfers value between addresses.

## BSV-specific terminology
**BSV**: The native token used for transactions on the BSV blockchain.

**BSV blockchain**: The public blockchain network using the original Bitcoin protocol rules.

**Paymail**: A protocol for human-readable payment addresses (user@domain.com format).

**BSV-21**: A token standard for creating non-fungible tokens on the BSV blockchain.

## UTXO model terms
**UTXO**: Unspent transaction output, representing spendable value in the system.

**Input**: A reference to a previous transaction output that is being spent.

**Output**: A destination for value in a transaction, with conditions for spending.

**Coin**: An unspent transaction output that can be used as input for new transactions.

## Cryptographic concepts
**Digital signature**: A cryptographic proof that a transaction was created by the owner of a private key.

**Elliptic curve cryptography**: The mathematical foundation for Bitcoin's signature scheme.

**Hash function**: A function that converts input data into a fixed-size string.

**Merkle tree**: A binary tree of cryptographic hashes used to efficiently verify large datasets.

**SHA-256**: The specific hash function used in Bitcoin for various cryptographic operations.

## Script and smart contracts
**Bitcoin Script**: A simple programming language used to define spending conditions.

**OP_RETURN**: An opcode that allows arbitrary data to be included in transactions.

**Script**: A program that defines conditions for spending transaction outputs.

**Covenant**: A script that constrains how outputs can be spent in future transactions.

## Network and protocol terms
**Node**: A computer that maintains a copy of the blockchain and validates transactions.

**Miner**: An entity that validates transactions and produces new blocks.

**Mempool**: The collection of unconfirmed transactions waiting to be included in blocks.

**SPV**: Simplified Payment Verification, a method to verify transactions without a full blockchain copy.

## Development terms
**SDK**: Software Development Kit, libraries for building applications on BSV.

**API**: Application Programming Interface, methods for interacting with services.

**Testnet**: A separate blockchain network used for development and testing.

**Mainnet**: The main BSV blockchain network where real value transactions occur.
